# second_llm_rag
Мой второй, более масштабный чем первый, проект по ML, где я сделал LLM-сервис с RAG-пайплайном.

Проект работает с тремя форматами входных данных для корпуса текстов: `.md`, `.pdf`, `.txt`. 
Проект реализуется на основе моего [первого проекта по LLM](https://github.com/Alisa-gh2/first_llm_wth_rag) . Были учтены недочеты и проблемы того проекта, так что в текущем мы постарались их исправить по максимуму.

В файле [ANNOTATION.md](https://github.com/Alisa-gh2/second_llm_rag/blob/main/ANNOTATION.md) находится подробное описание проекта и того, с чего и как мы начинали.

Сами файлы хранятся в [docs/](https://github.com/Alisa-gh2/second_llm_rag/blob/main/docs).

Был проведен исследовательскиф анализ корпуса текстов, проверена валидность текстов, а также файлы были предварительно очищены от лишних пробелов, табуляций и разрывов слов. Далее тексты были приведены к общему виду, то есть все форматы (`.md`, `.pdf`, `.txt`) были приведены к `.txt`. 

После этого файлы сохраняются в [clean_docs/](https://github.com/Alisa-gh2/second_llm_rag/blob/main/clean_docs). 

В файле [DATA_INFO.md](https://github.com/Alisa-gh2/second_llm_rag/blob/main/DATA_INFO.md) более подробно описано как мы работаем и с какими данными. 

## 2 части проекта

Был разработан сервис для локального развертывания модели на базе Ollama, однако на практике она оказалась слишом тяжелой для тестирования на рядовом ноутбуке. Всвязи с этим было  принято решение создать реализацию локального сервиса для обращения по API к модели на сервере OpenRouter. Идея в том, что мы предобрабатываем файлы и приводим к общему виду, после чего делим обработанный текст на чанки, строим эмбеддинги и далее создаем запрос к модели. Модель получает запрос и топ-k чанков, на основе чего она генерирует ответ и возвращает нам в сервис. Таким образом удалось решить проблему с недостаточными вычислительными мощностями устройства, на котором проводилось тестирование. 

Однако несмотря на то, что основной образ проекта теперь нацелен на работу по API, вариант локального развертывания можно использовать, он полностью протестирован и отвечает всем заявленным требованиям. Сервис с локальным развертыванием модели на базе Ollama представлен [здесь](https://github.com/Alisa-gh2/second_llm_rag/blob/main/colab/RAGv2.ipynb). 

Вариант с обращением по API к OpenRouter представлен [здесь](https://github.com/Alisa-gh2/second_llm_rag/blob/main/colab/RAGv3_with_openrouter.ipynb)

# Установка

## Windows 

Проект можно установить как контейнер для Docker. Для этого нужно:

1) Склонировать репозиторий:

```
git clone https://github.com/Alisa-gh2/second_llm_rag.git
```

2) Перейдем в папку проекта и создадим папки для локальных логов  и записи результатов индексации:

```
cd second_llm_rag
mkdir logs faiss_index
```

3) Разыменовываем файл `.env.example` в `.env`, и прописываем в него свой API-KEY с OpenRouter.

4) Выполняем первичную сборку контейнера:

```
docker build -t second_llm_rag
```

5) Установим зависимости:

```
docker run --rm -v ${PWD}:/app --user root -m 6g second_llm_rag bash -c "pip install -r requirements.txt"
```

6) Выполним индексацию очищенных текстов:

```
docker run --rm -v ${PWD}:/app --user root -m 6g second_llm_rag bash -c "python scripts/index_data.py"  
```

Примечение: к этому моменту предобработанные очищенные тексты должны быть расположены в папке clean_docs. Если же это не так, то следует заранее их предобработать в ноутбуке [EDA](https://github.com/Alisa-gh2/second_llm_rag/blob/main/colab/EDA.ipynb). 

7) После успешно выполненной индексации запустим контейнер:

```
docker-compose up --build 
```

# Использование

После поднятия сервиса по адресу http://localhost:8000/docs будет доступен Swagger UI данного проекта со всеми активными API. 

## У сервиса доступно 3 API-эндпоинта:

### 1) POST /ask – вопрос от пользователя.

Задается параметрами:
- question - вопрос от пользователя текстом
- top_k - по какому топ-к будет поиск, сколько итоговых чанков должна использовать модель для ответа
- include_sources - выводить (true) или не выводить (false) источники, то есть найденные чанки

В ответ пользователь получает такие параметры, как:
- answer - ответ модели
- sorces - использованные источники, то есть найденные топ-к чанков
- time_taken - время, затраченное моделью на генерацию ответа

#### Шаблон запроса:
```
{
  "question": "string",
  "top_k": 5,
  "include_sources": true
}
```

#### Шаблон ответа:
```
{
  "answer": "string",
  "sources": [],
  "time_taken": 0
}
```


### 2) GET /health – проверка состояния.

Возвращает состояние сервиса, а именно:
- status - статус сервера
- model_loaded - загружена ли модель в сервисе (true/false)
- index_loaded - загружены ли индексы (true/false)
- openrouter_model - какая именно модель загружена (название)

#### Шаблон запроса: 
```
{
    # он не требует задания параметров
} 
```

#### Шаблон ответа:
```
{
  "status": "ok",
  "model_loaded": true,
  "index_loaded": true,
  "num_chunks": 3660,
  "openrouter_model": "z-ai/glm-4.5-air:free"
}
```

### 3) /docs

Это эндпоинт, ведущий к веб-интерфейсу (Swagger UI) с описанием всех эндпоинтов и в целом структуры запросов. С него можно выполнять запросы по другим API. 

## curl

Помимо обращений через веб-интерфейс предусмотрена возможность обращения через curl, например:

### Для Windows:

```
curl.exe -X POST "http://localhost:8000/ask" -H "Content-Type: application/json" -d "{\"question\": \"Что такое общая политика сервиса Яндекс еда?\", \"top_k\": 5}"
```

### Для Linux:

#### /ask
```
curl -X POST "http://localhost:8000/ask" \
  -H "Content-Type: application/json" \
  -d '{
    "question": "Что такое общая политика сервиса Яндекс еда?",
    "top_k": 5,
    "include_sources": true
  }'
```
#### /health
```
curl -X GET "http://localhost:8000/health"
```

## Возможные будущие улучшения и интеграция в бизнес

В будущем рассмтаривается вариант расширить функционал, например добавив возможность выбора модели из списка доступных. Будут также рассматриваться варианты оптимизации индексации, поскольку в некоторых случаях она требовала слишком много ресурсов компьютера, и приходилось урезать параметры чанкинга, переранжирования и других механихмов в проекте. 

Планируется также работы по оптимизации реализации локального развертывания модели, что имеет огромный смысл с общемировыми тенденциями на блокировку онлайн-контента и сервисов. Имея локальную LLM можно тажке получить весомое преимущество перед конкурентами в бизнесе, используя ее, например, для оптимизации работы в команде, а именно:
- Освобождение экспертов от часто задаваемых вопросов стажеров и новичков о внутренней документации и другим темам.
- Благодаря этому у экспертов появляется больше времени и лучшая концентрация конкретно на своих рабочих обязанностях, что позволяет повысить продуктивность работы.
- Тем, от кого исходт вопрос (стажеры и новички в компании), в свою очередь не приходится ждать "когда у специалиста будет перерыв чтобы ответить на вопросы" - они получают ответ на вопрос здесь и сейчас, даже не отрываясь от рабочего компьютера.
- Локальное развертывание исключает ситуацию с утечкой конфиденциальных корпоративных документов в открытый доступ, поскольку локальная модель работает лишь в пределах физического периметра компании.
