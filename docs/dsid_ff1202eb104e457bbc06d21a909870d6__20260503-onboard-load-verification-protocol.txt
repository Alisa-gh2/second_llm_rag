Following our kickoff last week, attaching a first-pass load verification protocol for Skyline Health. Goal here is to make the acceptance gate explicit so your engineering team and ours know what success looks like for production rollout. High level:

- Acceptance targets (staging -> dedicated capacity):
  - Latency: p95 <= 220ms, p99 <= 480ms for typical 512-token prompts; tail measured as end-to-end API call (network + inference).
  - Throughput: sustained 120 RPS for 10 minutes on our dedicated staging pool; spike test to 240 RPS for 60s to validate autoscale/fallback.
  - Error budget: <= 0.5% 5xx rate during sustained tests.

- Test plan:
  1) Baseline single-client replay using synthetic production-like prompts (we provide generator).
  2) Gradual ramp: 1 -> 10 -> 50 -> 120 RPS (5 min each), then a 60s spike to 240 RPS.
  3) Variant runs: with KV cache warm vs cold, and with/without batching enabled.
  4) Long-run soak: 2 hours at 120 RPS to surface memory leakage or degradation.

- Environment and data handling:
  - Tests run against your dedicated staging cluster (credentials to be provided by ops+qa).
  - No real PHI will be used in test payloads; we will synthesize representative token lengths and instruction patterns.

- Deliverables:
  - Load test plan (attached v1)
  - Raw metrics CSV and aggregated dashboard snapshot after each run
  - A short post-test findings note with remediation items if targets are missed
